# 계정 수업·학생 결과를 원래 PPT로 가져오기 · 2026-10-21

## 구현

가이랩 v0.77.0에서 온바탕 첫 화면과 편집기의 **내 계정 수업**을 연결한다. 첫 화면에서는 빈 그림을 만들지 않으며, 편집 중에는 먼저 저장하고 같은 작업 영역에서 수업 목록·수업방 복구·저장 결과를 연다. 목록은 계정 소유의 요약만 읽고, 상태 필터/더 보기/수동 새로 확인을 제공한다. 기본 자동 polling은 없다.

저장 결과에서 **원래 PPT로 결과 가져오기**를 누르면 실제 PNG·선택한 답과 원래 PPT 전체 쪽 목록을 보여 준다. 넣을 위치와 충돌한 편집본을 교사가 선택하고, **가져와 저장하고 편집하기**로 결과 슬라이드를 추가한다. PNG와 답은 서로 다른 편집 요소다. 수업 앱·기존 쪽·원본 PPT bytes·이전 고정 revision은 유지한다.

## 저장·보존 계약

- 운영의 기존 account_rooms/room_recover/room_results/get_revision API를 재사용한다. **SQL·운영 DB·Auth·RLS·bucket·요금제 추가 변경 없음. 유료 QA·추가 AI 요청 없음.**
- 인증된 수업의 고정 결과와 선택 provenance를 검사한다. URL이나 임의 결과 JSON을 권한으로 삼지 않는다. PNG/텍스트만 복사하며 앱 HTML/실행 코드는 가져오지 않는다.
- 서버 복제본의 publishOrigin과 활동 쪽 origin을 원래 로컬 PPT ID·고정 버전·원본 SHA256과 대조한다. 파일 이름으로 다른 PPT를 추측해 덮어쓰지 않는다.
- 기기에 원래 자료가 없으면 원래 자료가 있는 기기에서 가져오도록 설명한다. **계정 수업방 복구**와 **원래 PPT 전체 자료의 기기 복구**는 다르다. 후자의 완전 자동 복구를 구현했다고 보고하지 않는다.
- 전체 자료의 모든 파트와 쪽 순서를 한 IndexedDB 트랜잭션으로 고정한다. 한 파트가 꽉 차면 같은 비율의 다른 파트 여유 공간을 쓰고 전체 순서상 선택 위치를 유지한다. 전체 200쪽·모든 파트의 용량 부족은 쓰기 전에 중단한다.
- 원본 쪽/앱을 바꾸지 않고 fresh page/element ID와 서버 결과 출처·digest를 부여한다. 같은 room/document/revision/page 결과는 다시 넣지 않는다. 가져온 뒤 교사가 바꾼 답도 재가져오기로 덮어쓰지 않는다.
- 초안/고정본의 동시 변경을 확인하고 CAS한다. quota/충돌은 원자적으로 보존한다. 저장 응답이 유실되면 정확한 고정 결과를 receipt로 확인한다. 고정 저장 후 초안 전달 실패는 이미 완료한 고정 저장을 실패/롤백으로 오인하지 않는다.
- 새로 가져온 결과는 원래 기기 PPT 전체 자료의 새 고정본이다. 기존 서버 결과 revision을 덮어쓰거나 기기 편집 내용을 자동 계정 백업했다고 표시하지 않는다. 편집 후 기존 **전체 자료에 저장**으로 다시 고정하고 재열기한다.
