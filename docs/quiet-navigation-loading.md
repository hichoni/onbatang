# 빠른 쪽 이동의 로딩 깜빡임 · v0.26.4

사용자가 확인한 잔상은 슬라이드 아래에 ‘몇 쪽을 여는 중’ 안내가 순간적으로 나타났다 사라지는 것이었습니다. 선택 테두리나 디자인/출력 데이터는 변경하지 않습니다.

편집기의 자료 목록 연결과 파트 이동 안내는 400ms 대기 후에도 작업 중일 때만 DOM과 접근성 알림을 만듭니다. 빠른 완료는 예약을 취소하므로 표시/안내가 없습니다. 실제 느린 작업에 표시된 안내는 최소 200ms를 유지하되 작업 완료·입력 허용을 지연하지 않습니다. 다음 이동이나 편집기 종료는 이전 표시와 타이머를 즉시 정리합니다. 가져오기·변환·보관함의 기존 로딩은 유지합니다. 실제 진행 보고가 없는 곳에 백분율을 만들지 않습니다.

브라우저 회귀는 실제 IndexedDB 응답을 느리게 한 이동에서 안내와 고정된 목록 배치를 확인합니다. 정상적인 빠른 파트 이동은 안내 DOM이 추가되지 않고 완료 후 늦게 표시되지 않는지 검사합니다. 표시 직후 완료·예약 취소·편집 가능 여부도 검사합니다. 기존 화면/목록/스크롤 안정화·저장/재열기·PPTX 출력 검증은 유지합니다.

원본·고정본·기존 PR·운영 DB를 보존하고 QA DB나 요금제 변경은 사용하지 않습니다. 실제 기기·실제 계정 검수는 별도입니다. 로컬 검사와 실제 배포 증거는 완료 기록에 구분합니다.

로컬 검증은 공통 단위 182개·브라우저 14개, 가이랩 관련 단위 40개·브라우저 9개·build를 통과했습니다. 실제 19쪽/11파트 PPT는 양쪽 각각 12항목을 통과했고, 빠른 19쪽 이동에 로딩 안내 추가가 0회였습니다. 화면/목록 위치와 높이 변화도 0px이며 원본·이전 고정본·편집 저장·재열기·두 PPTX 출력을 보존했습니다. 교사 자료는 로컬 Git 제외 work/에만 보관합니다.

[공용 배포 증거](qa/2026-10-19-quiet-navigation-firebase.json). 가이랩 PR #85는 운영 merge commit `4407ffc572e16bf2571ebb1935c6a07c769a0647`로 병합됐습니다. 가이랩 실제 운영 결과는 그 저장소의 완료 기록에 구분합니다. 실제 계정/기기·이번 출력의 PowerPoint 직접 검수는 미완료입니다.
