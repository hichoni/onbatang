# PPT 작업 중 다른 도구 이동 · v0.24.0

PPT 가져오기는 **그림 열기 → 내 자료 → PPT → 내 PPT 올리기**에서 시작한다. 독립 앱의 대문에 있던 PPTX 가져오기 버튼은 제거했다. 기존 프로그래밍용 `openPptx()`와 직접 주소의 호환성은 유지하며, 새 PPT 편집을 끝내고 ‘내 그림’을 누르면 실제 그림 목록으로 돌아간다. 전체 자료 보관함은 같은 내 자료 안의 ‘이미 가져온 자료 보기’로 연다.

## 다른 작업으로 이동

가져오기 중 상단·옆 메뉴를 통째로 `inert` 처리하지 않는다. 글·사진·툴·다른 도구·내 그림을 누르면 제공자의 `requestClose({reason:'navigate',action})`를 먼저 확인하고, 화면이 실제 닫힌 뒤에 해당 동작을 실행한다. 제공자가 거부하거나 저장 중이면 그림 변경이나 화면 전환을 실행하지 않는다. 이름 입력도 같은 확인을 거치며 승인 전에 글자가 바뀌지 않는다. 작은 화면에서도 도구 막대를 사용할 수 있다.

독립 앱은 최대 한 개의 미완료 작업 DOM·서비스·파일·글꼴 설정·선택 쪽·재시도 영수증을 메모리에 보관한다. 같은 창에서 다시 내 PPT 올리기를 누르면 그 작업을 붙인다. 검사 중 다른 도구로 이동한 경우 검사 결과는 보관하되, 숨겨진 화면의 미리보기를 다시 그려 편집기의 화면 비율을 바꾸지 않는다. 복귀 시 필요한 화면만 갱신한다. 저장 중에는 작업 완료 또는 저장 취소를 안내해 쓰기 중인 자료를 보호한다.

이 복원은 브라우저 종료·새로고침 이후 미저장 선택까지 복구한다는 뜻이 아니다. 이미 저장한 원본과 파트·고정본은 기기에 남는다. 완료된 가져오기는 다음 진입에서 새 작업을 시작하며, 부분 작업이 남아 있으면 새 파일로 초기화하지 않는다.

## 호스트의 전체 자료 저장 연결

`startMinican`은 선택적인 다음 계약을 지원한다. 순수 편집기에 원격 계정 SDK나 서버 스키마를 추가하지 않는다.

```js
materialAction: {
  label: '전체 자료에 저장',
  accepts: record => record.source?.kind === 'pptx',
  async open({designId, slideIndex}) {
    // 호스트의 전체 자료 보기·충돌 확인·새 고정본 저장 화면
  },
}
```

공통 앱은 현재 편집기 저장과 대상 계정 저장이 성공한 뒤 한 번만 `open`을 호출한다. 실패하면 호스트 고정 저장을 호출하지 않으며 현재 그림·선택 쪽·실행 취소 기록을 유지한다. 호스트 작업 중에는 그 그림을 더 바꾸지 않게 잠그고, 완료·취소 뒤 원래 편집기에 초점을 돌린다. 버튼은 `[data-material-action]`이며 호스트는 단일 대화상자를 앱 루트 밖에 붙일 수 있다. 실제 자료 소유권·초안 기준 revision·충돌·원자적 고정 저장은 호스트 책임이다.

`importAction.hideHome:true`는 대문의 가져오기 버튼만 숨긴다. `editorLabel`과 `editorMode:'inline'`은 내 자료 진입을 그대로 유지한다. 레거시 호스트가 이 옵션들을 생략하면 기존 동작을 유지한다.
