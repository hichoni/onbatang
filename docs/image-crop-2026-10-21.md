# 이미지 자르기 · 2026-10-21

## v0.33.1 · 캔버스 위에서 바로 자르기

**공용 배포 완료:** [PR #12](https://github.com/hichoni/onbatang/pull/12), 배포 원본 `9d18b4d2b2e30c1927738167bf0c6a02be244a53`. v0.33.1/version.json과 공개 171개 파일 전체 HTTP SHA256 일치를 확인했고 공개 화면에서 사진을 더블클릭해 실제 사진 위 자르기로 진입했다. 공통 전체 단위 208/208·실제 Edge 4/4를 통과했다.

작은 별도 미리보기 창으로 사용자를 이동시키던 v0.33.0의 조작 방식을 수정했다. 캔버스의 사진 **더블클릭**, 선택한 사진 **자르기** 단추, 선택한 사진에서 **Enter**로 같은 자리·크기·기울기의 자르기에 들어간다. 터치는 선택한 사진을 한 번 더 눌러도 진입한다. 잠긴 사진은 먼저 잠금을 풀어야 한다.

- 사진 위의 **모서리 4개·변 4개** 손잡이로 영역을 줄이거나 원본 범위까지 다시 늘린다. 영역 밖 원본은 흐리게 남고 안쪽에는 3등분 격자를 보인다.
- 사진 안쪽을 끌거나 방향키(Shift로 10px)로 사진을 옮겨 구도를 바꾼다. 사진을 옮겨도 자르기 틀의 슬라이드 위치·크기는 고정되며 원본 밖의 빈 공간이 생기지 않는다. 회전·좌우/상하 뒤집기도 같은 좌표로 동작한다.
- 도구 막대의 원본 전체·정사각형/4:3/16:9, **적용·Enter·사진 바깥 누르기·자르기 중 더블클릭**으로 완료한다. **취소·Esc**는 저장하지 않는다. 미리보기 중에는 자료·undo를 바꾸지 않고 적용 시 한 번만 기록한다. 다른 장으로 이동하거나 편집기를 치울 때 자르기 겹과 포인터 감시를 정리한다.

로컬 검증: 실제 Edge에서 더블클릭→사진과 겹의 위치/크기 일치→변 끌기→적용·단일 undo/redo·취소→IndexedDB 새로고침→동일 영역 PNG 픽셀·PPTX srcRect, 구도 이동 중 틀 고정, 회전/뒤집기 손잡이, 잠긴 사진, 390px 화면을 검사한다. 이 아래 v0.33.0의 배포·물리 기기 검증 범위와 구분한다.

## v0.33.0 · 최초 구현과 이전 배포

**공용 배포 완료:** [PR #11](https://github.com/hichoni/onbatang/pull/11)을 main에 병합하고 commit `571f4e2a7b1363cf5ed82ff8122873e3aa033b63`의 v0.33.0을 [onbatang.web.app](https://onbatang.web.app/)에 배포했다. 공개 171파일 전체 HTTP SHA256과 버전/원본 commit을 대조했다. 실제 공용 화면에서 사진을 자르고 저장·새로고침·재열기 후 왼쪽 25%·가로 50% 좌표 유지를 확인했다. 후속 문서 commit과 배포 제품 commit은 구분한다.

공통 온바탕 v0.33.0. 사진을 선택하고 **자르기**를 누른 뒤 모서리 손잡이 또는 왼쪽/위쪽/가로/세로 백분율로 영역을 정한다. 안쪽 끌기·방향키(Shift로 큰 이동), 원본 전체·정사각형·4:3·16:9, 적용·취소·Esc를 지원한다. 범위 밖·너무 작은 영역은 안내하며 저장하지 않는다.

`crop:{x,y,w,h}`는 원본 이미지 좌표 0..1이다. 원본 URL·자산·출처·ID를 유지하고 새 비트맵으로 덮어쓰지 않는다. 자른 영역의 픽셀 크기와 슬라이드 위치를 회전/뒤집기를 고려해 유지한다. 전체로 복원하면 잘려 보이지 않던 영역이 돌아온다. PPT에서 이미 래스터화해 가져온 자르기는 가져온 이미지 범위 안에서만 복원할 수 있다.

모델과 저장 경계가 잘못된 좌표를 거부한다. 취소는 원문을 바꾸지 않고 적용은 하나의 undo 기록이다. 저장·JSON 재열기·복제에서 crop을 유지한다. 화면/PNG/JPG/영상은 같은 렌더러를 사용하고 편집형 PPTX는 원본 이미지와 DrawingML `a:srcRect`를 넣어 PowerPoint의 그림 자르기로 유지한다. 모양 마스크가 있으면 기존 요소별 raster 경로를 쓴다. 원본 PPT bytes와 이전 고정본은 바꾸지 않는다.

근거: [Microsoft 사진 자르기](https://support.microsoft.com/en-us/office/graphics-visuals/crop-a-picture-in-office), [DrawingML SourceRectangle](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.sourcerectangle). 원본에서 영역을 가리는 방식과 출력 좌표 계약을 참고했다.

검증: 순수 계산 4개(회전/뒤집기 조합·원본 복원·저장 재열기/복제·잘못된 좌표)와 실제 Edge 1개(적용·취소·undo/redo·IndexedDB 새로고침·PNG 좌우/중앙 픽셀·PPTX srcRect·드래그·390px 가로 넘침 없음). 최초 브라우저 실행은 sandbox Edge 시작 실패였으며 허용된 로컬 실행으로 진행했다. 이후 검사의 선택 해제와 손잡이 범위 locator를 수정했으며 제품 동작 실패로 합산하지 않는다. 실제 물리 휴대폰/태블릿 및 이번 출력의 PowerPoint 데스크톱 재열기는 미검수다.
