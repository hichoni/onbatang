# 한 코드 수업방 운영 활성화 · 2026-10-21

## 최신 배치 보정 · v0.76.5

마지막 실제 결과 화면에서 제목과 PNG의 윗부분이 겹치는 것을 확인했다. 기존 8개 migration은 수정하지 않고 202610210002_onbatang_result_layout.sql을 추가했다. 새 결과의 제목/PNG 간격을 보정하는 함수 변경만 별도 트랜잭션으로 적용했고 전체 기존 고정 revision·제출 지문이 같은지 트랜잭션 안에서 확인했다. 이력은 이제 **기존 27 + 신규 9 = 36개**다. 권한·bucket·계정·기존 자료의 변경은 없다.

이미 저장된 초기 결과도 읽기 전용 화면에서 간격을 보정한다. 저장된 원문·PNG·revision을 덮어쓰지 않으며 새 저장부터 보정된 위치를 사용한다. 로컬 실제 SQL의 16:9 제목/PNG 비겹침, 이전 결과의 무변경 표시 보정, 반복 읽기의 멱등성을 검사했다.

## 실제 운영 적용

사용자가 테이블·비공개 저장소 추가를 명시 승인한 뒤 기존 운영 프로젝트 G-AI Lab dev에 적용했다. 별도 유료 QA 프로젝트·유료 플랜·추가 AI 요청은 사용하지 않았다. 기존 Auth 설정·계정·일반 그림 저장·AI 함수·배포 workflow를 바꾸지 않았다.

- 신규 public 테이블 10개와 private 순서 채점 매핑 테이블 1개, 비공개 onbatang-assets bucket, 소유권/RLS/RPC를 추가했다. 새 public 10개 모두 RLS 활성화, bucket public=false를 실제 catalog에서 확인했다.
- 기존 수동 적용 SQL 27개의 실제 객체 221개를 catalog와 대조했다. 누락 0. 이미 적용된 SQL을 다시 실행하지 않고 migration 이력에 baseline으로 기록했다. 새 SQL 8개만 단일 트랜잭션으로 적용했다. 이력 총 35개.
- 기존 계정 9개·일반 그림 6개, 기존 함수/정책 지문이 적용 전후 동일했다. 기존 4개 bucket과 그 객체는 유지했다. 설치 wrapper는 기존 자료 지문을 트랜잭션 안에서 재검사하고 다르면 rollback한다.
- 설치 이력 테이블에도 RLS를 켜고 anon/authenticated/PUBLIC 직접 접근을 revoke했다. 제안된 RLS 누락 경고가 있던 초기 검토는 취소하고 수정된 최종 SQL만 실행했다.
- 검토한 8 SQL을 바이트 변경 없이 supabase/migrations/에 승격했다. 첫 7개는 기존 draft PR #76과 같다. 이력 35개가 정식 파일 35개와 맞으므로 다음 db push가 이미 적용한 SQL을 재실행하지 않는다. 기존 전체 초기화 SQL을 다시 붙여넣지 않는다.
