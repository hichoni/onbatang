# 가이X 수업 앱 연결 · 2026-10-20

## 사용자 흐름

PPT를 내 자료에서 연 뒤 앱을 넣을 앞쪽 슬라이드를 선택합니다. 아래의 **가이X로 앱 만들기** → **가이X 연결** → 대화 → 미리보기 → **이 앱을 슬라이드에 넣기**를 사용합니다. 발표 화면에서 앱이 같은 자리에 실행되고, 교사가 **결과를 다음 슬라이드에 저장**을 누르면 실제 답·진행 상태와 그림판의 캔버스 그림을 일반 슬라이드로 저장합니다. 기존 활동 설정으로 돌아와 앱을 다시 고칠 수 있습니다. 생성 요청이 실패하거나 대화를 닫아도 원본 슬라이드와 마지막 적용 앱은 변경하지 않습니다.

공용 온바탕은 가이랩 출처의 작은 계정 연결 창을 사용합니다. 이미 가이랩에 로그인되어 있으면 연결 동의만 받고, 그렇지 않으면 가이랩에서 로그인합니다. 로그인 토큰·비밀번호는 편집기에 전달하지 않습니다. AI 요청은 기존 가이랩 서비스와 사용량 한도를 사용하며 신규 SQL·계정·유료 QA 프로젝트를 만들지 않습니다. 앱 제작 자체의 기존 AI 사용량과 유료 QA 환경은 서로 다른 항목입니다.

## 공유·실행·저장 계약

- `appMaker.connect()`는 `{label}`을 반환합니다. `generate({prompt,context,project,conversation},{signal,onProgress})`는 대화 응답 `{kind:'answer',answer}` 또는 `{kind:'app',activity:{title,instructions,document,project},summary}`를 반환합니다. `startMinican`에는 선택 사항이고 `startOnbatang`은 공용 팝업 연결을 기본 제공합니다. `appMaker:null`로 숨길 수 있습니다.
- 교사의 보내기 동작에서만 요청을 전달합니다. context는 제목·전체 쪽 수·선택 위치·슬라이드 순서·제한된 글이며, 사용자가 확인하거나 전달을 끌 수 있습니다. 원본 PPT와 사진은 AI 요청에 첨부하지 않습니다. 슬라이드 글은 명령이 아닌 참고 자료로 표시합니다. 대화 초안은 별도 로컬 IndexedDB에 현재 저장소·문서·쪽·revision별로 남습니다.
- `activity.kind:'gai-app'`은 앱 제목, 설명, 실행 문서, 수정할 프로젝트 원본과 checkpoint를 보존합니다. `document + project`는 UTF-8 420KB, checkpoint는 18KB 이하입니다. 공통 정리·migration·복제·고정 저장·재열기에 같은 검증기를 적용합니다. 기존 `pixel-art` 계약은 유지합니다.
- 가이랩이 만든 문서는 `appDocument(...,{standalone:false,classroom:{bridge,initial}})`로 기존 앱·장면 runtime을 포함합니다. bridge의 JSON 문자열 `ONBATANG_APP_BRIDGE_TOKEN`과 checkpoint 객체 `{"onbatangRestoreMarker":"ONBATANG_APP_CHECKPOINT"}`는 공통 실행기가 매 실행마다 새 채널과 저장한 상태로 치환합니다. 정리 함수는 코드를 실행하지 않습니다.
- 실행은 별도 origin의 sandbox iframe에서만 하며 `allow-scripts`만 허용합니다. 호스트 DOM·저장소·계정·카메라 권한을 주지 않습니다. 출처 창과 채널을 확인한 GAIClassroom 보고만 받고 상태·답·그림 크기를 다시 검사합니다. 외부 저장 버튼을 누를 때만 결과 쪽을 만듭니다.
- 저장은 기존 원자적 고정본·전체 쪽 순서 저장을 사용합니다. 원본 PPT·revision 0·과거 고정본을 덮어쓰지 않습니다. 다른 창의 편집 충돌이나 공간 부족은 실패로 안내하고 앱을 유지합니다. 앱과 첫 결과를 둘 수 있는 파트를 선택하며 한 파트 저장 한도를 초과하는 앱은 작게 만들도록 안내합니다.
- HTML 수업은 앱과 상태를 함께 담아 오프라인에서도 실행합니다. PPTX에는 앱의 표지와 저장한 결과가 정적 요소/이미지로 들어가며 JavaScript 실행 기능이 들어가지는 않습니다. 내려받은 HTML에서 추가한 결과가 원래 브라우저 자료에 자동으로 합쳐지지는 않습니다.

## 검증과 남은 범위

공통 단위 검사 197개를 통과했습니다. sandbox·오프라인 HTML 브라우저 검사 7개, 자체 21쪽 PPT와 실제 19쪽 수업 PPT의 1440px·390px 흐름을 검증했습니다. 실제 자료는 앱 삽입 후 20쪽, 결과 저장 후 21쪽이며 checkpoint를 두 번 재열어 확인했습니다. 대화 초안 복구·수업 글 전달 해제·미리보기 중 원본 불변·전체 순서·revision 0 보존을 확인했습니다.

실제 PPT SHA-256은 `c165d32bda450cec385e5bc916351c75d72b6acc69abdea5931d2d473f10d12d`이며 원본 파일과 화면 캡처는 Git에서 제외한 work에만 둡니다. 편집형으로 가져온 19쪽 모두 참고 글이 전달됐습니다. 이미지형으로만 가져온 쪽은 OCR을 제공하지 않으며 요청에 설명을 추가하도록 안내합니다.

로컬 UI 테스트는 결정적인 모의 가이X 응답을 사용하며 실제 모델 품질·실제 계정 인증/과금 검증으로 간주하지 않습니다. Edge/Playwright의 중첩 iframe 추적 문제로 자동검사에서만 프로세스 분리 옵션을 조정했습니다. 제품의 두 sandbox·CSP·저장소 격리는 유지합니다. 모바일 화면 자동검사는 실제 휴대폰/태블릿 검증과 구분합니다. 배포 commit과 공개 파일 해시 결과는 후속 배포 기록에 남깁니다.

실제 가이랩 계정으로 생성한 앱의 내용·학습 적합성, 외부 기기에서 계정 복구, 학생 수업방·35명 동시 참여는 별도 검증 범위입니다. 운영 DB는 변경하지 않습니다. 기존 PR #76의 신규 계정 수업방 기능을 이번 작업에 섞지 않습니다.
