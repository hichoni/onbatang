# 픽셀아트 PNG·답 결과 · 2026-10-20

v0.30.3의 공통 실행기는 교사가 ‘결과를 다음 슬라이드에 저장’을 누르면 최신 SDK 기록을 먼저 flush하고 PNG와 실제 answer를 한 결과로 저장한다. 결과 슬라이드는 PNG image 요소와 편집 가능한 답 text 요소를 함께 가진다. 앱 checkpoint와 결과는 기존 원자적 저장·고정 revision·전체 pageOrder 계약을 따른다. 공용 제작 숨김을 해제하거나 운영 DB를 바꾸지 않는다.

## PNG 지원

- 기존 canvas 캡처를 유지한다. 기존 한도(최대 256px, PNG data URL 40,000자)를 유지하며 외부 네트워크를 열지 않는다.
- 버튼형 픽셀 앱은 `data-onbatang-pixel-grid` 표면 또는 기존 `#pixel-grid`를 지원한다. 표면의 직접 자식이 각각 한 칸이며 2~32행/열, 최대 1,024칸의 완전한 직사각 격자여야 한다. 실제 표시 위치와 불투명 background-color를 읽어 칸 색만 PNG에 담는다. 선택 테두리·숫자 데이터 표·팔레트·버튼 글자는 그림에 섞지 않는다.
- 칸 누락·겹침·불규칙 크기/간격·투명 채움·배경 이미지 등 재현할 수 없는 표면은 PNG 생략을 명시하고 답·진행 기록은 보존한다. 일반 grid/table을 픽셀 그림으로 추측하지 않는다. 임의 HTML 앱 화면 전체를 스크린샷으로 만드는 기능은 아니다.
- 새 앱 제작 시 그림은 canvas 또는 위 명시적 픽셀 표면을 사용한다. answer에는 작품 제목·배운 점·필요한 개수 등 읽을 결과를, checkpoint에는 복구할 실제 상태를 담는다. 기존 앱 소스를 다시 생성하거나 덮어쓸 필요가 없다.
- opaque 이중 sandbox, bridge 출처·요청 확인, CSP `connect-src 'none'`과 PNG 검증을 유지한다. HTML 수업 번들도 같은 코드를 포함한다.

## 로컬 검증

- 버튼 격자 8×8의 (1,1)/(1,2)/(2,2)/(3,3) 네 칸과 나머지 흰색을 PNG 256×256의 64개 셀 중심 RGBA와 대조했다. 다른 색, 불완전 격자, 일반 grid 제외도 확인했다.
- 자체 제작 21쪽 PPT: 중간 앱 삽입 → 네 칸 상태 → PNG+답 다음 슬라이드 → 저장/새로고침/재열기 → 공용 진입 후 기존 앱/결과 실행을 확인했다. 원본 자산 해시·revision 0·기존 쪽 ID/상대 순서는 유지했다. 공용 제작 버튼 0과 활동 수정 숨김을 확인했다.
- canvas/버튼형 각각의 오프라인 HTML에서 결과 저장·새로고침·다운로드·새 브라우저 컨텍스트 재열기에 PNG/답/checkpoint가 남았다.
- 실제 교사 PPT의 양쪽 운영 저장·재열기 검수는 통합 인수인계 문서의 최신 절에서 별도로 기록한다. 로컬 표본·실제 계정·운영 검증을 혼동하지 않는다. 추가 AI 호출·유료 QA·운영 DB 쓰기 없음.
