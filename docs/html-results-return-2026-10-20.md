# HTML 수업 결과 반환 · 2026-10-20

## 사용자 흐름

1. 최신 온바탕에서 HTML 수업을 내려받는다. 원래 자료/문서 ID와 활동 페이지·활동 ID, 상태를 제외한 활동 정의 SHA-256을 함께 담는다.
2. HTML 수업에서 활동하고 결과를 다음 슬라이드에 저장한다. **온바탕용 결과 내려받기**를 누르면 `onbatang-results.json`을 만든다. 현재 수업 HTML 내려받기는 별도로 유지한다.
3. 원래 온바탕 자료 아래의 **HTML 수업 결과 가져오기**에서 JSON 파일을 선택한다. 결과 그림·답·이미 저장된 결과를 확인하고 선택한다.
4. **선택한 결과 저장**으로 새 결과 쪽과 전체 pageOrder를 한 고정 저장에 반영한다. 같은 파일을 다시 가져오면 기존 결과를 건너뛴다. 결과는 원래 활동 다음의 결과 묶음에 추가하며 기존 슬라이드·앱 진행 상태·이전 결과와 과거 revision은 바꾸지 않는다.

예전 HTML은 반환 연결 정보가 없으므로 최신 편집기에서 다시 내려받아 사용한다. 임의 HTML 파일을 실행/분석해 출처를 추측하거나 결과를 자동으로 합치지 않는다. 이 기능은 교사가 미리보고 가져오는 기기 파일이며 학생 인증·서명·서버 채점의 증거는 아니다.

## 계약과 저장

`app/lesson-results.js`가 `onbatang-html-results` v1 JSON을 정리·검증한다. 파일 20MB, 결과 100개 이하, 결과 PNG 2MB/4096px/8백만 픽셀 이하, 답 2000자, 전체 자료 200쪽과 문서당 20쪽·500KB 계획 제한을 적용한다. 외부 URL·SVG·중복 결과 ID·잘못된 연결은 거부한다. 미리보기에서는 PNG를 실제 디코딩한다. 파일의 스크립트나 앱 코드는 실행하지 않고 원래 자료의 활동만 비교한다.

원본 자료 ID가 다르거나 활동 ID/정의가 바뀌면 가져오지 않는다. 픽셀 셀/가이X checkpoint 등 진행 상태의 변화는 활동 정의 변경으로 간주하지 않는다. 원본 앱 상태는 덮어쓰지 않으며 결과 PNG와 답을 일반 요소로 보관한다. `source.kind:'result'`, `source.sourceDocumentId`(HTML 수업 ID), `source.objectId`(반환 결과 ID), `source.sha256`(정리된 결과 내용 해시), `origin`(원래 활동 쪽/문서/revision)으로 재열기 이후에도 중복을 판별한다. 같은 ID의 다른 내용은 기존 결과를 보존하며 거부한다.

크기/용량을 넘으면 어떤 결과도 저장하지 않는다. 선택 결과가 여러 기존 파트에 들어가면 공용 `library.pinEdits`와 가이랩 `repository.saveMaterialEdits`가 하나의 IndexedDB 트랜잭션으로 고정한다. 현재 초안과 예상 초안·고정본을 비교해 다른 창의 변경을 보호한다. 고정 저장 후 편집 사본 전달이 실패한 경우는 저장 완료/복구 필요 영수증으로 처리하며 롤백 성공으로 거짓 안내하지 않는다. DB schema·SQL·운영 계정 저장 경로는 변경하지 않는다.

## 검증과 한계

공통 단위 202개 통과. 자체 제작 PPT → HTML 활동 실행 → 결과 JSON 다운로드 → 미리보기 → 원래 자료 고정 저장 → 재열기 → 재가져오기 중복 방지 → 다른 자료 거부를 1440px·390px의 공용/가이랩에서 검증했다. 가이랩의 두 파트 원자 저장·두 번째 파트 용량 실패 롤백·동시 편집 보존과 기존 저장 회귀를 포함한 14개 브라우저 검사를 통과했다. 별도 공용 브라우저 검사 2개도 통과했다.

이 검사는 자체 제작 fixture와 로컬 HTTP에서 수행하며 실제 교사 다운로드 파일의 `file://` UI 재열기, 실제 학교 기기·학생·계정 서버 복구를 완료했다고 간주하지 않는다. 이전 자동 브라우저 정책의 로컬 파일 열기 제한은 우회하지 않는다. 실제 AI·유료 QA·운영 DB는 사용하지 않았다. main·공개 배포 결과는 통합 인수인계에서 별도로 갱신한다.
