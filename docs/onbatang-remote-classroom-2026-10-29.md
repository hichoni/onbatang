# 온바탕 수업 리모컨 · 2026-10-29

## 구현

기존 QR 리모컨과 Supabase Realtime broadcast 통로를 그대로 사용한다. 새 SQL·저장소·계정 변경은 없다. 공용 온바탕은 기존 `phone-remote.js` 다리로 같은 리모컨을 쓰고, 가이랩은 직접 연다.

- 현재 장과 다음 장의 그림·제목, 발표자 메모, 활동 표시를 휴대폰에 배치했다. 그림이 준비되지 않거나 전달되지 않으면 제목이 대신 보인다.
- 발표자 화면과 큰 버튼 화면을 전환한다. 다음 버튼은 키보드와 같은 경로여서 요소 나타내기·영상 재생·다음 장 넘기기를 잇는다. 숫자로 특정 장에도 간다.
- 리모컨을 연 뒤의 경과 시간과 1·3·5·10분 활동 타이머를 둔다. 활동 타이머는 휴대폰 안에서만 돌아가며 서버나 학생 화면에 보내지 않는다. 화면이 잠시 숨겨져도 실제 지난 시간을 기준으로 계산한다.
- 발표 화면에서는 링크를 복사하거나 리모컨을 잠시 잠글 수 있다. 잠겨 있는 동안 받은 조작을 나중에 다시 실행하지 않는다.
- 신호마다 임의의 request ID를 부여한다. 같은 패킷의 재수신은 한 번만 처리한다. 휴대폰은 수신 확인 전 겹친 입력을 막고, 확인 실패·오프라인·발표 응답 지연을 표시한다. 끊긴 동안의 다음 장 명령을 자동 재전송하지 않는다.
- 연결 확인·재연결·화면 깨움·진동은 가능한 브라우저에서만 사용한다. 연결이 끊기면 재연결을 안내하며 조작을 보냈다고 표시하지 않는다.

## 전달 범위

긴 무작위 키는 기존처럼 URL fragment에 있고 발표가 끝나면 채널을 닫는다. **리모컨 링크 소지자는 발표를 조작하고 발표자 메모를 볼 수 있다.** 학생 참여 링크와 구분해 교사만 사용한다.

`onbatang-remote-protocol.js`는 장 위치를 검사하고 제목·메모 길이를 제한한다. 작은 PNG·JPEG·WebP data URL만 미리보기로 받으며 외부 그림 주소·SVG·과도하게 큰 그림은 버린다. 계정·문서 전체·원본 파일은 전송하지 않는다. 썸네일은 발표 쪽 `remoteState()`의 `preview`·`nextPreview`, 화면 상태는 `black`·`activity` 선택 필드다. 예전 발표 쪽과도 제목 기반으로 동작한다.

중복 방지 장부는 발표별 최근 256개 ID만 기억한다. 그보다 오래된 패킷의 임의 재전송까지 영구 차단하는 장부는 아니다. 휴대폰은 유실된 명령을 자동 재전송하지 않으며, 이 통로를 결과 저장처럼 반드시 한 번만 실행해야 하는 쓰기 작업에 사용하지 않는다.

## 참고

발표자가 휴대폰에서 메모를 보는 구성은 [Canva 공식 도움말](https://www.canva.com/help/presenting-designs/), 현재·다음 슬라이드와 메모의 관계는 [Microsoft의 발표자 보기](https://support.microsoft.com/en-us/powerpoint/training/use-presenter-view-in-powerpoint)를 참고했다. 디자인·코드는 새로 작성했다. 제품 간 기능 우열이나 독점 기능을 주장하지 않는다.

## 검증 경계

- 단위: 리모컨·공용 다리 **11/11 통과** (`test/onbatang-remote.test.mjs` · `onbatang-remote-upgrade.test.mjs` · `onbatang-remote-relay-origin.test.mjs`). 상태 제한·썸네일 거르기·중복 패킷·교사 잠금·휴대폰 ACK·ACK 유실·전송 실패·오프라인 재연결·이전 채널의 늦은 응답·타이머·출처 사칭을 검증한다. 같은 통로를 사용하는 질문·반응·투표·퀴즈의 회귀도 함께 **19/19 통과**했다. 공유 통로의 SDK 결과 문자열 계약은 유지한다.
- 기존 로컬 Headless Edge 회귀: `test/browser/onbatang-remote.test.mjs`, `onbatang-remote-relay.test.mjs` **2/2 통과**. 가이랩 직접 연결과 공용 다리 연결을 기존 임시 BroadcastChannel 통로로 검증한다.
- 새 UI 브라우저 회귀 `test/browser/onbatang-remote-upgrade.test.mjs` **1/1 통과**: 390×844 화면에서 두 그림·메모·큰 버튼·쪽 이동·활동 타이머·교사 잠금·오프라인/재연결을 확인한다. 이 과정에서 처음 연결 때의 자동 숨김 예약이 사용자가 다시 펼친 리모컨을 덮는 문제를 발견해, 다시 펼치거나 만지면 예약을 취소하게 고쳤다.
- 추가 검토에서 이전 채널의 늦은 상태가 새 연결에 들어오는 것을 막았다. ACK는 수신 확인이며 쪽 이동 완료로 표시하지 않는다. 두 썸네일의 합산 용량도 제한한다. 출처·창·channel 사칭 방어는 `test/onbatang-remote-relay-origin.test.mjs`에서 별도 검증한다.
- 실제 Supabase 계정·실제 휴대폰·Wi-Fi 망의 리모컨 조작 검수와 운영 배포는 이 변경의 로컬 검증과 구분한다. 유료 QA는 사용하지 않았다.
