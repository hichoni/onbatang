# 온바탕 인수인계 · 2026-11-02 · 슬라이드 모핑과 카메라 직접 편집

후속 **오프라인 HTML 모핑은 0.116.0에서 구현·운영 반영을 완료**했다. 최신 운영 기록과 다음 할 일은 [오프라인 모핑 인수인계](ONBATANG_HANDOFF_2026-11-02_OFFLINE_MORPH.md)를 먼저 본다. 아래는 0.115.0 배포 당시 기록이다.

## 이번 구현

제품 0.115.0 / GBE-AI Lab 0.169.0. 이전 [모션 관찰 순서 인수인계](ONBATANG_HANDOFF_2026-11-02_MOTION_CUES.md)의 첫 번째 후속 과제를 구현했다. 원본 체크아웃은 main `360f4e51e09509a68b1066339bef16fc1ad6e994`, 가이랩은 main `2d522ac49f1c118478d38f6971216ee28b54a589`에서 시작했다.

- **움직임 → 모핑 · 카메라 직접 편집**에서 앞 장·도착 장을 나란히 본다. 같은 종류의 요소를 각각 골라 직접 연결하며 세 장 이상으로 연결을 이어갈 수 있다. 연결 해제 및 자동 연결 복귀도 제공한다.
- **카메라 구도**에서 앞 장 또는 도착 장을 고르고 드래그로 중심을 이동한다. 1~4배 확대와 가로·세로 중심을 수치로 고칠 수 있다. 전체 화면 복귀는 선택한 쪽에만 적용한다.
- 0.6/1/1.6/2.4/3.2초 이동과 두 가지 출발·도착 리듬을 선택한다. 기존 0.4~4초 값도 보존한다. 실제 발표의 DOM 모핑 엔진으로 재생·되감기·중간 프레임을 확인한다.
- 뒤로 넘길 때도 같은 이동 시간을 사용한다. 기존 브리딩이 모핑의 중간 자세를 덮어쓰지 않으며 도착 뒤 이어진다. 시스템 동작 줄이기는 발표에서 존중한다. 편집 창의 명시적 재생·시간 막대는 검수를 위해 동작한다.
- 자료에 적용하기 전에는 임시 편집이다. 되돌리기 30단계와 취소가 있으며 원본 요소의 좌표·글꼴·ID·출처·자산 참조를 바꾸지 않는다. 원래 배치는 편집기에 남고 발표·썸네일·정지 출력에 카메라 구도를 사용한다.
- 여러 파트로 저장한 PPT는 전체 쪽 순서에서 편집한다. 바뀐 파트만 IndexedDB의 **단일 transaction**으로 저장한다. 다른 창의 변경을 비교하고 충돌/저장 실패 시 전체 저장을 취소한다. 기존 계정 동기화 및 호스트 저장 알림을 그대로 사용하며 DB·SQL은 추가하지 않았다.
- 작은 화면에서는 세로로 배치하고 저장 버튼을 하단에 유지한다. 키보드 Tab/Enter/Space로도 요소를 고를 수 있다.

## 사용 순서

1. 두 장 이상 있는 자료를 열고 **움직임 → 모핑 · 카메라 직접 편집**을 누른다.
2. 위쪽 목록에서 도착 장을 고른다. 양쪽 요소를 하나씩 고르고 **선택한 두 요소 연결**을 누른다. 다음 장에서도 같은 요소를 연결하면 한 흐름으로 이어진다.
3. **카메라 구도**에서 장을 드래그하거나 확대·중심을 바꾼다. 첫 장 구도는 **앞 장 카메라 편집**으로 고친다. 전체→세부→전체처럼 구성할 수 있다.
4. 이동 시간·리듬을 선택하고 **전환 재생** 또는 시간 막대로 확인한다.
5. **자료에 적용·저장** 후 발표한다. 다시 열면 연결·카메라·시간이 유지된다.

## 데이터와 파일

- `src/slide-flow.js`: 선택적 `slide.camera={x,y,z}`, `slide.travel={ms,ease}`, `item.morphKey` 정리·투영·연결. 카메라가 종이 밖을 드러내지 않도록 중심을 확대 배율에 맞춰 제한한다.
- `morphKey`: `m`으로 시작하는 영숫자 연결 ID. `off`는 자동 연결 제외. 명시적 연결은 기존 ID/출처/내용 자동 매칭보다 우선한다. 같은 장에 두 요소가 한 체인으로 겹치는 모호한 병합은 안내하고 거절한다.
- `app/slide-flow-panel.js`: 편집·미리보기·모바일 UI. `app/app.js`: 전체 자료와 저장 연결. `app/store.js`: 여러 파트 compare-and-swap transaction. 기존 단일 자료 API는 그대로 호환된다.
- `src/model.js`, `app/designs.js`: 기존 스키마의 선택적 필드로 보존. 기존 자료에는 필드를 억지로 추가하지 않는다. 장 복제 시 연결을 보존한다. ‘모든 장에 똑같이’는 장마다 다른 카메라 구도를 복사해 덮지 않는다.
- `src/render.js`, `src/export.js`, `app/pptx.js`, `src/film.js`, `src/video.js`: 원본 기하를 고치지 않고 표시·출력 시 한 번만 투영. 영상 타임라인에 전환 길이를 반영한다.
- 공용 원본을 확정 커밋한 뒤 가이랩 `scripts/sync-onbatang.mjs`로 동기화한다. 직접 vendored 파일을 수정하지 않는다.

## 경계와 다음 작업

- 사진·글·도형 등 정적 슬라이드 요소가 대상이다. 활동·영상·웹·실시간 바탕이 있는 장은 전체 화면을 유지하며 카메라 편집을 비활성화한다.
- 현재 카메라는 장별 중심·확대와 그 사이 이동이다. 임의의 곡선 경로, 회전 카메라, 한 장 안의 다중 카메라 키프레임은 아직 없다. 비슷한 사진 속 객체를 AI로 인식해 자동 매칭하지 않는다.
- PPTX·PNG는 최종 카메라 구도를 출력하며 PowerPoint 네이티브 Morph 애니메이션으로 변환하지 않는다. 내려받은 HTML 수업도 현재 정지 슬라이드 이미지를 사용하므로 카메라 최종 구도는 담기지만 새 요소별 모핑 전환은 재생하지 않는다. 기존 HTML 그래픽 효과·관찰 순서·활동은 유지한다.
- 다음 개발 우선순위: ① HTML 수업에 장별 모핑 런타임을 포함하되 파일 용량·오프라인 동작 유지 ② 원본 교사 PPT의 다양한 글상자·그림·복잡한 효과에서 장 연결 검수 ③ 실제 iPhone의 터치 중심 이동·세로/가로 전환·동작 줄이기 확인. 단순히 예제 수를 늘리기보다 이 경로를 완성한다.

## 보존

원본 PPT·기존 자료·기존 PR·운영 DB·SQL은 변경하지 않았다. GBE-AI Lab의 기존 `dist/community-config.js`, `release-times.json` 로컬 변경은 원래 바이트를 보존하고 이번 커밋에서 제외한다. 유료 QA와 AI 생성 요청을 사용하지 않았다.
