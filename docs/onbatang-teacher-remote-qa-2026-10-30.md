- 다운로드 폴더의 원본은 읽기만 했다. Git에서 제외되는 `work/`에 복사하고, 공용·가이랩 각각 새 임시 Edge 브라우저 저장공간에서 실제 가져오기 UI로 열었다.

- 공용은 실제 standalone → phone-remote → relay 경로, 가이랩은 실제 내장 편집기 → 직접 리모컨 경로를 사용했다. 실시간 전송만 로컬 BroadcastChannel로 대체했고 가이랩 계정 연결은 로컬 fixture다. 외부 HTTP·WebSocket 요청은 차단했다.

화면 크기는 320×568, 390×844, 667×375, 844×390, 768×1024, 1024×768을 확인했다. 가로 넘침이 없고 타이머·앞뒤 버튼이 화면 안에 남는다. 48px 프롬프터는 작은 화면에서도 부모 영역·하단 버튼에 가리지 않는 한 줄 이상의 실제 표시 높이를 측정했고, 대표 세로/가로 캡처를 직접 살폈다. 좁은 화면에서 가로형을 고르면 세로 배치와 회전 안내를 유지한다.

## 재현과 비공개 증거

가이랩의 `scripts/qa-onbatang-teacher-remote.mjs`를 명시적으로 실행한다. 기본 테스트에서는 개인 PPT를 읽지 않는다.

```powershell
$env:ONBATANG_REMOTE_QA_PPTX='검수할 PPTX의 절대 경로'
$env:MINICAN_PLAYWRIGHT_PATH='설치된 playwright/index.mjs의 절대 경로'
node scripts/qa-onbatang-teacher-remote.mjs
```

최종 성공 기록: `g-ai-lab-inline/work/qa-teacher-remote-20261030-b8X0o6/report.json`. 각각의 `common/`, `gai/`에 상세 보고서·세로/가로 화면·48px 프롬프터·마지막 장 캡처가 있다. 운영 대조는 `work/qa-teacher-remote-production-20261030.json`. PPT 사본·캡처·개인 자료는 Git에 올리지 않았다.

처음 실패한 실행도 work/에 보존했다. 공용 검수용 HTML의 mc-app 클래스 누락, 노트 헤더 중앙 대신 왼쪽 라벨을 눌러야 하는 위치 선택, 전체 자료 이름과 파트 이름을 혼동한 재열기 locator를 바로잡았다. Playwright의 serviceWorkers:block 주입이 격리된 미리보기 iframe에서 SecurityError를 만드는 것도 확인하고, 같은 등록 차단을 try/catch로 감싼 초기화로 바꿨다. 제품의 iframe 격리나 보안 정책을 완화하지 않았다. 최종 검수 도구는 자료 ID로 홈의 전체 자료 카드를 찾는다. 이 검수 절차 오류를 제품 기능 오류로 집계하지 않는다.
