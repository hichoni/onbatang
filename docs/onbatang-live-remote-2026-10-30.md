# 운영 리모컨 연결 검수와 화면 정리 — 2026-10-30

## 완료와 검수 범위

공용 `onbatang.web.app/app/`과 가이랩 기본 화면 `gbe.ai.kr/#/onbatang`에서 새 5장 검수 자료(배움 신호)를 만들어 발표했다. 공용은 relay, 가이랩은 사용자가 직접 로그인한 실제 계정과 직접 연결 경로를 사용했다. QR에 담긴 리모컨 주소를 별도 브라우저 탭으로 열어 **운영 Supabase Realtime**으로 조작했다. 이 검수는 로컬 BroadcastChannel fixture 검수와 별개다.

| 항목 | 공용 운영 | 가이랩 운영 |
|---|---|---|
| QR 표시와 QR에 담긴 주소 연결, 현재·다음 그림 | 통과 | 통과 |
| 다음·앞 장 한 번씩 1→2→1 | 통과 | 통과 |
| 3분 시작·카운트다운 | 통과 | 통과 |
| 리모컨 페이지를 닫는 이동 후, 발표자가 2쪽으로 이동, 뒤로 돌아와 재연결 | 2/5 복구 | 2/5 복구 |
| 재연결 후 진행 중 타이머 복원 | 00:15로 계속 | 02:17로 계속 |
| 복구 후 다시 앞 장 조작 | 1쪽으로 이동 | 앞선 앞뒤 이동 및 명시적 재연결 확인 |

공용에서는 별도로 타이머 멈춤·1분 추가·계속을 확인했다. 공용 첫 세션에 한 번 누른 뒤 여러 쪽 이동이 관찰됐지만, 사용자의 동시 조작 가능성이 있어 결함으로 확정하지 않았다. 새 발표 코드로 재검수한 한 번씩의 조작은 정확했다. 종료한 발표의 지난 코드가 연결되지 않는 것과 살아 있는 발표에 재연결하는 것을 구분했다.

**사용자가 실제 휴대폰에서 리모컨이 정상 동작한다고 직접 확인했다.** 이는 사용자 확인으로 기록하며, 에이전트가 수행한 데스크톱 브라우저 검수와 구분한다. 휴대폰 기종·OS·가로/세로·Wi-Fi/LTE 전환·화면 잠금 복귀·진동 각각은 이번 응답으로 확인되지 않았다. 에이전트의 복구 검수는 페이지/채널 종료 후 재접속이며 실제 무선 네트워크 단절 검수가 아니다.

이번 운영 검수는 직접 만든 5장 자료다. 실제 19쪽 실과 PPT를 사용한 앞선 로컬 검수는 [별도 기록](onbatang-teacher-remote-qa-2026-10-30.md)에 보존한다.

## v0.159.0 화면 개선

사용자 피드백: 기능은 실제 휴대폰에서 작동하지만, UI 전체가 더 깔끔하고 완성도 있기를 원함.

- 세로: 현재 슬라이드는 넓은 한 장, 다음 장은 작은 미리보기와 제목이 있는 가로 카드로 구분한다.
- 가로: 짧은 화면에서도 현재·다음 그림이 하단 버튼에 가려지지 않도록 두 미리보기와 노트를 나란히 배치한다.
- 발표자 노트가 없으면 빈 큰 박스·글자 조절기를 접는다. 프롬프터를 선택하면 읽기 영역과 16~48px 조절은 그대로 제공한다.
- 조작 설정을 상단 한 곳으로 모으고 화면 배치 선택도 그 안에 둔다. 자동 배치가 기본이며 연결이 원활할 때 재연결 버튼을 눈에 띄지 않게 한다.
- 짙은 전체 하단 대신 밝은 타이머와 큰 녹색 ‘다음으로’ 버튼을 사용한다. 현재/전체 쪽 수를 한글로 표시하고 중복 영문·보조 문구를 줄였다.

원격 명령·ACK·중복 방지·잠금·통신 프로토콜은 변경하지 않았다. `dist/onbatang-remote.html`, `onbatang-remote-view.css`, 노트 유무에 따른 표시 상태 1줄만 변경한다. 공용과 가이랩은 같은 `gbe.ai.kr` 리모컨을 사용하므로 이 배포로 양쪽에 적용된다. 공통 편집기 원본 v0.105.0 / `09eb31401389e4da3c935ad552dd110a96404bd5` / 252파일은 그대로다.
