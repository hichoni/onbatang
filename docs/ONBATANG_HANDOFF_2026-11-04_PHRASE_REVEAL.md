# 온바탕 인수인계 · 클릭과 리모컨으로 구절 공개

2026-11-04 · 공용 0.124.0 · 가이랩 0.178.0

## 사용법

글 조각의 **시네마 효과 / 효과 수정 → 발표 방식 → 클릭·리모컨으로 하나씩 공개**를 고르고 슬라이드에 적용한다. **화면 · 타임라인 편집**에서도 발표 방식을 고를 수 있다. **움직임 저장**으로 이름 붙이면 이 방식도 프리셋에 함께 저장된다. 기존 프리셋은 불러온 뒤 이 옵션을 켜 새 이름으로 저장할 수 있다. 기존 자료와 프리셋을 자동으로 변경하지 않는다.

발표에서는 다음 순서로 동작한다.

- 글 조각을 누르거나 발표의 ‘다음’·리모컨 ‘다음’을 누르면 아직 실행하지 않은 구절 공개 장면을 열고 첫 구절을 재생한다. 같은 슬라이드에 여러 장면이 있으면 문서의 요소 순서대로 진행한다.
- ‘장이 열릴 때’를 지정한 경우에는 장면만 열고 첫 입력을 기다린다. 다른 자동 효과가 대기 중인 장면을 덮지 않게 예약을 취소한다.
- 화면·**다음 구절 보기**·→·PageDown·리모컨 ‘다음’이 같은 명령을 사용한다. 동작 중 다음을 누르면 **현재 구절만 완성**하고 다음 입력을 기다린다. 빠른 연속 입력을 예약해 두지 않는다.
- **이전 구절**·←·PageUp·리모컨 ‘이전’은 마지막 구절 하나를 다시 숨긴다. **처음부터**는 공개 전으로 돌아간다. 모든 구절 공개 후 다음 입력은 원래 슬라이드로 복귀하며, 그다음 입력부터 다음 장으로 이동한다. Esc는 먼저 구절 장면을 닫는다.
- 구절 공개 슬라이드는 자동 넘기기에서도 교사의 입력을 기다린다. 탭이 숨겨지면 진행 중인 구절을 멈추고, 돌아와 다음을 누르면 남은 부분을 이어 재생한다.

## 순서와 시간 계약

현재 지원하는 시네마 효과 다섯 종의 **글이 있는 트랙**을 대상으로 한다. 박자 오프닝의 구절, 스포트라이트/종이 지평선 제목, 롤링 숫자의 숫자판·설명, 탐사 항로의 단계다. 해·능선·조명 같은 배경은 별도 클릭 단계로 세지 않는다.

1. 실제 렌더링 트랙의 등장 시각을 오름차순 정렬한다. 시각이 같으면 기존 화면·타임라인의 안정적인 순서를 따른다.
2. 프리셋에 저장한 구절별 움직이는 시간을 그대로 사용한다. 효과의 재생 속도도 반영한다.
3. 첫 등장 전 지연과 구절 사이 양의 빈 시간도 유지한다. 원래 겹치던 구절은 개별 입력으로 나누어 재생한다. 교사가 입력을 기다린 실제 시간은 원래 타임라인 시간을 다시 늘리지 않는다.
4. 완료한 구절은 완성 상태로 유지한다. 현재 구절은 자기 시간만 재생하며 아직 공개하지 않은 구절은 원래 시간이 지나도 숨긴다. 탐사 항로의 선·지점·단계 글도 같은 공개 상태를 따른다.

저장 필드 `effect.reveal:'step'`는 선택 필드다. 값이 없던 자료는 연속 재생을 그대로 유지한다. 관찰대 `observe`와 동시에 켜지면 하나씩 공개가 우선하며 정리 과정에서 observe/stops를 제외한다. 기존 원문·ID·배치·출처·PPT 원본을 변경하지 않는다.

## 구현

- `src/cinema-cues.js`: 정렬·시간·빈 시간 계산. 실제 표시되는 글 트랙만 포함한다.
- `src/cinema-layout.js`: 일반 트랙과 연결된 선·지점에 `data-cinema-cue`를 부여한다.
- `src/effect-frames.js`: 원래 전체 타임라인 `paint()`를 유지하고 트랙별 시간으로 그리는 `paintCues()`를 추가한다.
- `src/cinema-step-player.js`: 하나씩 공개 화면, 빠른 다음 처리·이전·리셋·키보드·탭 복귀·좁은 화면. DOM 프레임 재생으로 Safari에서도 명시적 입력에 따라 동작한다. 매 프레임 같은 상태 문구를 다시 읽게 하지 않는다.
- `src/effect-player.js`: 공통 ‘다음/이전’ 중재, 미실행 장면 열기, 다른 효과 예약 취소, 전환 중 프레임 정지와 핸들러 정리. 공용·가이랩 리모컨은 기존 `showRemote.command → go → stepOpenQuestion` 경로를 사용한다. 새 서버·DB·리모컨 채널을 추가하지 않는다.
- `app/app.js`, `app/html-lesson-runtime.js`: 자동 넘기기 대기 및 키 이벤트 충돌 방지. 읽기용 `app/player.js`도 기존 공통 중재 경로로 연결된다.
- `cinema-controls.js`·`cinema-studio.js`: 발표 방식 UI. `cinemaSettings`의 정리 계약으로 보관함 저장·가져오기에도 모드가 보존된다.
- `build:pptx-import`와 `build:html-lesson`으로 배포 번들을 생성한다. 가이랩은 확정된 원본 commit을 공식 sync로 들인다.

## 검증과 한계

- 단위 검사 420개. 순서·동시 시작·겹침·빈 시간·재생 속도, 기존 자료의 연속 재생 보존, 프리셋 왕복, HTML 대상 정리를 검사한다.
- `stepped cinema` 브라우저 검사: UI로 다섯 효과의 모드를 설정하고 이름 있는 프리셋 저장/불러오기 → 슬라이드 저장 → 새로고침/재열기 → 호스트 리모컨 어댑터의 실제 command 콜백으로 진행 → 겹치는 구절 은닉 → 빠른 입력 → 이전·리셋 → 탭 숨김/복귀 → 자동 넘기기 대기 → 오프라인 HTML 다운로드·진행·재열기.
- `cinema step opening`은 자동 시작이 교사를 기다리는지, 다른 예약 효과를 취소하는지, 슬라이드 전환 시 프레임 정지와 기존 속성 복구를 확인한다.
- Edge/Windows WebKit, 자체 제작 6장 자료, 390×844·844×390·320×740 화면을 사용한다. 기존 직접 편집·보관함·일반 효과·질문 공개 회귀도 확인한다. 최종 결과와 배포 해시는 작업 폴더 통합 인수인계에 기록한다.
- 리모컨 검수는 무료 로컬/운영 브라우저의 **호스트 어댑터 명령 계약** 검사다. 실제 휴대폰 QR 연결·네트워크·잠금 후 복귀의 이번 버전 현장 검수와 실제 개인 수업 PPT/교사 계정 검수는 별도 미완료다. 내려받은 HTML은 클릭·키보드·PageDown/PageUp 프레젠터로 진행하며 오프라인 파일에 휴대폰 QR 중계 서버를 새로 내장하지 않는다.
- 프리셋·문서의 연출을 보존하며, 발표 중 공개한 현재 단계까지 영구 저장하는 기능은 아니다. 새로 열면 처음부터 시작한다. PPTX의 PowerPoint 클릭 애니메이션이나 MP4로 변환하는 기능도 이번 범위가 아니다.
- 유료 QA·AI 호출·운영 DB 변경 없음. 원본·기존 변경·PR 이력을 보존한다.
