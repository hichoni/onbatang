# 온바탕 V2 · 편집기부터 다시 정리하기

2026-11-02. 현재 운영 기준은 온바탕 0.116.0, 가이랩 0.170.0. 여기서 V2는 제품 경험의 다음 세대를 뜻하며, package 버전을 2.0.0으로 올렸다는 의미는 아니다.

## 사용자와 합의한 범위

- 온바탕 편집기부터 정리한다. 가이랩 전체 개편은 이번 첫 범위에 포함하지 않는다.
- 기존 PPT를 고쳐 수업하는 일과 새 자료를 디자인해 발표하는 일을 같은 비중으로 지원한다.
- 기능이 많아진 상태에서 UI를 먼저 정리하고, 버전 2라고 부를 만큼 제품 경험을 발전시킨다.

이 문서와 대화의 두 구조 시안은 첫 설계안이다. 운영 편집기 교체·제품 코드 변경·데이터 이전은 아직 하지 않았다. 실사용자 테스트 결과나 확정된 개발 일정으로 읽지 않는다.

## 현재 화면에서 확인한 문제

로컬 0.116.0을 새 Edge 브라우저에서 자체 작성한 4장 자료로 확인했다. `work/editor-v2-audit/audit.json`과 화면 캡처가 근거다. 이 폴더는 Git에서 제외되므로 다른 PC에서는 아래 코드 위치와 조건으로 재확인한다.

50개는 스크롤 영역 전체의 버튼 수이며 한 화면에 동시에 보이는 수가 아니다. 화면 크기·선택 상태·호스트 연결에 따라 도구 수가 달라진다. 현재 화면에도 자동 저장, 선택에 따른 툴바, 접기 기능은 이미 있다. V2는 그 기능을 새로 발명하는 것이 아니라 분산된 역할과 위치를 일관되게 만드는 작업이다.

## V2의 핵심 경험

**자료를 시작하고 → 내용을 다듬고 → 수업 흐름을 만들고 → 목적에 맞게 사용하는 하나의 편집기.**

첫 화면에서는 ‘새 자료 만들기’와 ‘PPT 가져오기’를 같은 수준의 주요 진입으로 둔다. 이후에는 같은 편집 화면을 쓴다. 카드/포스터/슬라이드 같은 크기는 새 자료 만들기에서 선택하고, 열고 난 뒤의 비율 변경은 문서 설정에 둔다. 가져온 자료에는 원본과 편집 가능 상태를 실제 데이터에 맞게 표시한다.

### 권장 구조: 장 중심

- 상단: 자료 제목, 실제 저장 상태, 문서 메뉴, 발표, 공유·내보내기.
- 왼쪽: 장 목록과 전체 순서. 일반 자료와 여러 파트 PPT도 같은 전체 순서로 보여 준다.
- 가운데: 캔버스. 기본 삽입 진입은 ‘추가 / 자료 / 디자인’으로 묶는다.
- 오른쪽: 선택한 글·사진·도형·복수 선택의 속성. 아무것도 고르지 않으면 현재 장 설정. 상세 위치·겹 순서 등은 여기서 펼친다.
- 작업 전환: ‘편집 / 움직임’. 발표는 별도 실행 상태이며 종료하면 같은 장·선택·편집 맥락으로 복귀한다.
- 노트: 현재 장 아래에서 필요할 때 펼친다. 작은 화면에서는 장 목록과 속성을 각각 명확한 진입으로 열고 캔버스 가시성을 보존한다.

대안 ‘캔버스 집중’은 장 목록을 하단으로 두어 한 장 디자인 공간을 넓힌다. 여러 장 순서 편집의 가시성은 떨어진다. 먼저 장 중심을 검토하고, 실제 한 장 디자인 작업에서 이점이 확인될 때 집중 배치를 추가하는 순서를 권한다. 처음부터 사용자에게 여러 레이아웃 설정을 요구하지 않는다.

### 같은 기능을 찾는 위치

| 기존 기능 | V2의 기본 위치 | 보존 조건 |
| --- | --- | --- |
| 글·도형·그림 조각·수식 | 추가 | 삽입과 이미 있는 요소의 속성 변경을 구별 |
| 사진·PPT·영상·웹·온바탕 파일 | 자료 / 시작 화면 | 현재 장 추가인지 새 자료 열기인지 명시, 현재 자료 저장 경로 유지 |
| 틀·디자인 세트·팔레트·바탕 | 디자인 / 현재 장 속성 | 적용 범위 ‘선택/현재 장/전체 자료’를 명시, 취소·되돌리기 유지 |
| 글꼴·색·크기·crop·정렬·겹 순서 | 선택 속성 | 같은 조작은 같은 위치, 키보드 포커스·복수 선택·잠금 보존 |
| 조합·등장·강조·반복·사라지기 | 움직임의 선택 요소/장 구성 | 기존 효과 값을 손실 없이 읽기, 단순 선택 후 세부값 펼치기 |
| 장 전환·모핑·카메라 | 움직임의 장 사이 연결 | 앞 장/도착 장/전체 자료 범위를 명확히 하고 같은 엔진으로 재생 |
| 그래픽 관찰·RGB 수업·활동 | 수업용 도구와 선택 대상의 연결 | 독립 온바탕/가이랩/학생 임베드가 제공하는 기능 범위 유지 |
| 이력·공동 편집·비율 | 문서 메뉴 / 상태 | 기능 삭제 없이 정리, 저장 실패·동시 편집 보호 유지 |
| 파일 형식 9종 | 목적별 공유·내보내기, 상세 형식 선택 | 모든 기존 출력 경로를 유지하고 데이터 보존 차이를 안내 |

수업용 기능은 호스트가 허용한 경우에만 나타난다. 지금 공용에서 숨기는 앱 제작 기능을 UI 개편을 이유로 다시 노출하지 않는다.

## UI를 넘어 V2로 발전시킬 세 가지 축

1. **자료 전체의 디자인 일관성.** 장별 임시 색·폰트 변경을 넘어서 자료의 기본 글꼴·색·스타일과 재사용 구성을 다룬다. 기존 PPT의 서식을 일괄 덮지 않도록 적용 범위와 원본 보존을 먼저 설계한다.
2. **내용과 수업 흐름을 함께 편집.** 장 순서, 모핑·카메라, 요소 등장, 관찰 순서, 활동과 결과가 어떤 대상·시점에 작동하는지 같은 구조에서 설명하고 미리 본다. 기존 엔진과 저장 계약을 활용한다.
3. **사용 목적에 맞는 결과물.** 오프라인 수업, PPT 전달, 인쇄/이미지, 영상, 링크 공유, 편집 원본 보관으로 안내한다. 선택한 결과물에 움직임·활동·외부 미디어가 어떻게 남는지 실제 기능 계약으로 보여 준다.

기능 추가 수, 예제 개수, 버전 번호만으로 V2 완료를 판단하지 않는다. 새 사용자도 두 시작 경로에서 편집·수업 준비·출력까지 흐름을 이해할 수 있어야 한다.

## 구현 순서와 완료 기준

| 단계 | 범위 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 1 · 편집기 골격 | 새 자료/PPT의 동등한 진입, 상단·장 목록·캔버스·선택 속성의 역할 정리. 한 화면을 실제 코드로 완성 | 기존 자료 열기·선택·삽입·실행 취소·장 이동·저장·재열기 통과. 1024px에서 주요 도구와 캔버스 접근, 키보드 조작 확인 |
| 2 · 도구와 디자인 | 추가/자료/디자인 재배치, 사진·텍스트·복수 선택 속성, 문서 스타일의 적용 범위 | 서로 다른 두 시작 경로에서 같은 조작의 위치가 같음. 원본 PPT·기존 스타일·취소·저장 계약 보존 |
| 3 · 수업 흐름과 출력 | 움직임의 대상별 UI, 노트·관찰·활동의 연결, 목적별 내보내기 | 모핑·발표·오프라인 HTML·결과 되가져오기·PPTX 등 기존 기능 회귀 통과. 내보내기 안내와 실제 출력이 일치 |
| 4 · V2 공개 검수 | 자체 표본/허용된 교사 PPT, 실제 사용자 작업, 태블릿·실제 Safari, 독립/가이랩/임베드 호환 | 아래 시나리오를 모두 완료하고 치명적 회귀 없이 공개할 수 있음. 초보/기존 사용자 관찰 결과로 메뉴 이름·기본 노출 조정 |

다음 실제 구현은 **1단계 편집기 골격**이다. 기존 로직을 전면 재작성하지 않고 화면 구조를 분리한다. `app/app.js`의 저장·자료 전환 제어와 `src/editor.js`의 선택·명령·저장 데이터 계약은 유지한다. 기존 DOM을 복제해 두 개의 속성 패널을 만드는 방식은 피하고 각 도구의 소유 위치를 하나로 정한다. 미리보기 진입을 분리해 기존 편집기와 같은 자료로 비교할 수 있게 한다.

## V2 공개 전 검수 시나리오

- 빈 자료에서 제목·사진·도형을 추가하고 장을 복제·재배치한 뒤 저장·재열기.
- 기존 PPT를 열고 한 장을 수정하고 여러 파트의 순서를 다룬 뒤 원본과 편집 결과를 구분해 보관.
- 글/사진/복수 선택/잠근 요소/빈 장에서 적합한 속성만 표시되고 입력·포커스·실행 취소가 유지됨.
- 모핑·카메라를 설정하고 편집기 미리보기, 발표, 내려받은 HTML의 결과가 일치함.
- 활동 결과 저장과 HTML 재다운로드, 결과 JSON 되가져오기, 중복 결과 보호 유지.
- 출력별 기능 보존 안내 확인. 이미지/PDF/PPTX에 HTML 모핑이 그대로 들어간다고 약속하지 않음.
- 저장 실패·다른 창의 수정·빠른 이동·동작 줄이기·작은 화면에서도 작업을 잃지 않음.
- 독립 온바탕·가이랩 내장·학생 임베드의 권한/도구 차이와 기존 자료의 호환성 확인.

## 이번에 준비한 것

현재 UI를 브라우저로 살펴보고 구조 문제와 기능 이동표를 작성했다. 대화에서 ‘장 중심’과 ‘캔버스 집중’ 두 구조를 비교할 수 있다. 장 이동, 제목 속성, 움직임 시간 막대, 발표/복귀, 자료 진입과 목적별 내보내기를 조작할 수 있는 시안이다. 실제 편집 엔진, 파일 가져오기/생성, 저장·동기화는 연결하지 않았다.

시안은 Edge에서 제목 변경·모핑 진행 조작·출력 목적 선택·발표 복귀·구조 전환과 1024/768/390/320px 가로 넘침, 밝은/어두운 테마를 확인했다. 제품 접근성 검수나 실제 iPhone 확인을 마친 것은 아니다. 시안의 모바일 배치는 비교용이며 실제 구현에서 키보드·도구 패널과 캔버스 높이를 다시 검수한다.

현재 작업 브랜치는 `codex/onbatang-v2-ui-20261102`다. 운영 변경은 없으며, 이전 오프라인 모핑은 [배포 마감 기록](ONBATANG_HANDOFF_2026-11-02_OFFLINE_MORPH.md)에 보존되어 있다. 이후 우선순위는 이 사용자 요청에 따라 UI/V2 개편으로 전환한다. 기존 PPT·기기·성능 후속 검수는 폐기하지 않고 V2의 검수 조건으로 이어간다.
