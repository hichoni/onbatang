## 전체 PPT를 계정으로 옮기는 사용 경로

1. 원래 자료가 있는 기기에서 **전체 자료에 저장**을 연다.
2. 저장할 초안과 전체 미리보기를 확인하고 **계정에 전체 PPT 백업**을 누른다. 일반 그림의 자동 동기화와 다른 명시적 백업이다.
3. 다른 기기에서 같은 가이랩 계정으로 로그인한다.
4. **내 계정 수업 → 내 계정 PPT · 새 기기 복구 → 미리보고 이 기기에 복구**를 연다.
5. 전체 쪽 미리보기 확인 후 **확인한 전체 PPT를 이 기기에 복구**한다. 복구한 자료를 편집하고 **전체 자료에 저장**으로 새 고정본을 만든다.

원본 PPT bytes·모든 파트·전체 쪽 순서·문서/쪽/요소 ID·원본 크기·사진/crop·앱과 진행 상태·이미 가져온 학생 결과·기존 고정 버전과 연결 snapshot을 보존한다. 서버의 기존 수업방/학생 제출은 복제하지 않고 내 계정 수업에서 다시 연다. 자세한 계약은 [전체 PPT 백업](https://github.com/hichoni/g-ai-lab/blob/main/docs/onbatang-whole-ppt-backup-2026-10-21.md)에 있다.

## 이번 누락 점검

- 백업 생성뿐 아니라 **목록/더 보기 → 전체 미리보기 → 빈 기기 복구 → 재편집 → 고정 저장 → 새로고침 재열기**를 확인한다.
- 같은 내용 재백업·응답 유실·중간 업로드 실패·손상·저장 공간 부족·계정 전환/다른 소유자·기존 고정본/초안 충돌을 구분한다. 실패한 자료를 완료 목록에 표시하지 않는다.
- 원본·이전 고정본·다른 초안은 보존한다. 전체 검증 후 IndexedDB 한 트랜잭션으로 복구한다. 고정본 복구 후 초안 준비 실패는 고정본 복구 실패로 표시하지 않는다.
- **미지원**: 별도 영상 장면이 들어 있는 자료의 계정 전체 백업, 임시/외부 이미지 주소, 백업 삭제·이름 변경·용량 관리 UI. 앞의 두 경우는 원격 쓰기 전에 안내하고 중단한다. PPT 원본 파일 자체는 보존한다.
- 파일당 50MB, 백업 1회 256MB, 전체 200쪽, 연결 고정 snapshot 10,000개 한도. 수정 후 최신 상태를 다른 기기로 가져가려면 다시 백업한다.
- 일반 편집 후속: 사진 교체 시 위치/크기 유지, 전체 슬라이드 글 찾기/바꾸기. 이 기능들을 이번 백업 구현에 포함했다고 표시하지 않는다. [누락 점검표](https://github.com/hichoni/g-ai-lab/blob/main/docs/onbatang-feature-audit-2026-10-21.md).

## 함께 반영되는 공통 편집기

- 사진 더블클릭/자르기 → 실제 캔버스에서 8개 손잡이와 사진 이동. Enter/바깥 누르기 적용, Esc 취소, 단일 undo와 저장·PNG/PPTX 출력 유지.
- 아래 목록은 기본 64px 썸네일과 작은 이동 막대. **···**에 장 복제·삭제·순서·활동/앱·HTML 결과 도구를 모았다.
- 경계를 끌어 **창 전체 높이(px)**를 조절하고 같은 기기·브라우저의 계정 저장 공간별로 기억한다. 창 축소 때 잠시 제한했다가 다시 늘리면 고른 높이를 복원한다. 다른 기기로 높이 설정을 동기화하지 않는다.
- 터치 썸네일/손잡이 탭은 쪽 선택, 6px 이상 이동은 순서 변경이다. 관련 공통 단위 208/208·브라우저 고유 11개를 통과했다.
