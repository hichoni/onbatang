## 사용 경로

1. 원래 자료가 있는 기기에서 **전체 자료에 저장 → 계정에 전체 PPT 백업**. 먼저 선택한 초안을 전체 고정본에 저장한다.
2. 새 기기의 같은 계정에서 **내 계정 수업 → 내 계정 PPT · 새 기기 복구**.
3. **미리보고 이 기기에 복구**에서 전체 쪽과 영상을 확인한 뒤 **확인한 전체 PPT를 이 기기에 복구**. 다시 편집·전체 저장·재열기를 이어간다.
4. 계정 PPT 목록의 **이름 변경**으로 표시 이름만 바꾼다. 원본 제목과 백업 내용은 유지한다.
5. **백업 삭제 → 보관함으로 이동**. **삭제한 백업 → 백업 목록에 복원**으로 되돌린다. 기기의 원본·이미 복구한 자료·공유한 고정 버전을 지우지 않는다. 보관함 이동은 저장 용량을 비우는 영구 삭제가 아니다.

## 보존 범위와 저장 계약

원본 PPT bytes·모든 파트·쪽 순서·문서/쪽/요소 ID·원본 크기·사진/crop·앱/체크포인트·이미 가져온 학생 결과·현재 파트의 이전 고정 버전과 연결 snapshot을 보존한다. 서버의 기존 수업방/학생 제출은 계정 수업에서 다시 연다. 일반 그림 자동 동기화와 달리 수정 뒤에는 다시 명시적으로 백업한다.

- 별도 영상 장면은 **원본 영상 bytes·이름표·재생 구간·음량·화면 맞춤**까지 보존한다. 같은 영상을 여러 쪽에서 쓰면 파일은 한 번 보관한다. MP4·WebM·MOV/M4V를 지원하며 실제 재생 가능 코덱은 해당 브라우저를 따른다. 원본 PPT 안의 파일은 원본 PPT bytes에 보존한다. 외부 유튜브는 주소를 보존하며 영상을 내려받아 백업하지 않는다.
- 기존 비공개 자산 API의 JSON snapshot으로 원본 영상을 4MiB씩 나누어 저장한다. 조각 순서·길이·SHA256·MIME와 전체 원본 hash를 검증한 뒤 완료 목록을 만든다. 형식 v2이며 이전 v1 백업도 복구한다.
- 복구는 모든 원본·파트·고정 이력·영상을 검증한 뒤 IndexedDB assets/heads/revisions/**videos**를 한 트랜잭션으로 저장한다. 로컬 DB v1→v2 업그레이드는 기존 3개 저장소를 유지한다. 검증 전 미리보기는 기기 고정본을 쓰지 않는다.
- 이름 변경·삭제/복원은 소유자 검사와 예상 catalog revision의 CAS를 사용한다. 불변 원본 snapshot은 유지한다. 다른 창의 변경·응답 유실·계정 전환을 확인한다. 다른 창에서 삭제된 백업은 복구 직전에도 차단한다.
- 영상과 자산 한 개 50MiB, 인코딩을 포함한 전체 전송 256MiB, 200쪽, 연결 고정 snapshot 10,000개 한도. 원본이 없거나 손상된 영상·임시/외부 이미지 주소·초과 용량은 첫 원격 쓰기 전에 중단한다. 이미 잃어버린 과거 영상 원본을 만들어 복구할 수는 없다.
- 기존 초안·더 최신인 고정본·같은 이름표의 다른 영상·원본 충돌은 전체 취소하고 보존한다. 고정본 복구 후 초안 준비 실패는 별도 안내로 재열기를 제공한다.
