## 3. 현재 제공되는 제품 흐름

1. **내 자료 → PPT → 내 PPT 올리기** 안에서 파일 선택·원본 화면 미리보기·쪽 선택·글꼴 안내/전체 및 슬라이드별 교체·가져오기까지 진행한다. 바깥 별도 가져오기 화면으로 나가는 흐름을 기본으로 되살리지 않는다. 다른 도구로 이동·취소·미완료 작업 복원·현재 편집 저장을 보호한다.
2. 원본 크기·16:9/4:3/사용자 비율을 유지한다. 50MB·200쪽 범위에서 큰 PPT는 내부적으로 파트에 나누어 저장하고, 교사가 직접 쪽을 쪼개지 않아도 전체 순서로 편집·활동·수업에 연결한다. 원본 파일·문서/쪽/요소 ID·출처·자산 참조·revision 0·과거 고정본을 보존한다.
3. 편집기에서 슬라이드 가로 이동·순서 변경·직접 스포이드·팔레트 1~4, 기본 자유 크기 조절과 Shift 비율 유지 등을 제공한다. 로딩은 온바탕 심벌 조각이 모이는 방식이며 빠른 이동에는 깜빡이는 안내를 만들지 않는다.
4. PNG/JPG·편집형/이미지형 PPTX·HTML 수업을 내려받는다. PPTX에는 앱의 정적 표지·저장된 결과가 들어가며 JavaScript 앱 실행은 HTML 수업에서 한다. 편집형에도 지원하지 못하는 요소는 이미지 fallback이 있을 수 있다.
5. 수업 만들기는 ‘이 자료로 수업 만들기’와 교사 자유시간 방향이다. 시간·수업 계획·활동의 로컬 구현/계약과 실제 계정 서버 수업방 운영 적용을 분리한다. 기존 PR #76의 SQL/서버 기능이 운영에 모두 제공되는 것으로 표시하지 않는다.
6. **가이X로 앱 만들기 → 계정 연결 → 수업 흐름을 참고한 대화 → 미리보기 → 슬라이드에 넣기 → 발표 안 실행 → 결과를 다음 슬라이드에 저장**이 동작한다. 외부 앱 링크로 이동하는 방식이 기본이 아니다. 앱 코드와 checkpoint를 자료에 보관하고 HTML에도 담는다.

## 4. 저장·보안 경계

- 공용 PPT와 가이랩 PPT 작업 공간의 원본·파트·초안·고정본·앱·결과는 **이 브라우저 IndexedDB**에 저장된다. 가이랩에 로그인했다는 사실을 PPT 계정 백업 완료로 표시하지 않는다. 가이랩의 기존 일반 그림 계정 저장 경로는 유지하지만 `source.kind === 'pptx'` 자료는 그 동기화에서 제외한다. 자세한 기준은 가이랩 `docs/minican.md`.
- 실제 가이랩 계정 AI 생성은 기존 서비스의 한도/이용량을 사용한다. 유료 QA 프로젝트를 쓰지 않았다는 말은 AI가 무과금이라는 뜻이 아니다. 최근 실제 검수에서 AI 요청 7회 중 6회 완료·1회 시간 초과가 있었고, 이용량/환급 여부는 별도로 확인하지 않았다. 이번 비교 UI 수정에서는 추가 AI 요청을 하지 않았다.
- `activity.kind:'gai-app'`은 실행 document·수정용 project·state를 보존한다. document+project 420KB, checkpoint 18KB 제한과 정리 검증이 있다. `pixel-art` 계약도 유지한다.
- 앱은 opaque sandbox iframe, `allow-scripts`만으로 실행한다. CSP·출처/보낸 창·bridge 확인·상태/그림 크기 검사를 유지한다. 인증 토큰·호스트 DOM·저장소 접근을 앱에 주지 않는다. 자동 검수 편의를 위해 제품 sandbox·CSP를 약화하지 않는다.
- 저장은 전체 pageOrder와 새 고정본을 원자적으로 반영한다. 다른 창의 실제 초안 충돌은 비교/선택을 요구하며 조용히 덮어쓰지 않는다. 파트 ID·원본 쪽 번호는 전체 표시 순서를 바꿔도 변경하지 않는다.

## 5. 이번 수정

이전 비교 화면은 파트 payload 순서로 미리보기를 평탄화해 앱·결과가 잘못된 앞쪽에 보였다. 원본 번호도 같은 배열 위치의 다른 쪽에서 빌려와 중복 표시했다.

- 공통 `app/material-preview.js`: `materialPreviewPages`가 전체 쪽 ID 순서를 적용한다. `materialPageDescription`/`materialPageLabel`은 원본 PPT 번호와 새 앱·활동·결과를 구분한다.
- 공용 `app/pptx-import/app.js`: 보관함 전체 자료의 쪽 이름도 같은 공통 표시를 사용한다.
- 가이랩 `dist/onbatang-material-editor.js`: 선택한 초안들을 전체 `graph.pages` 순서로 표시한다. 초안 선택을 바꿔도 현재 쪽 ID를 유지한다. 데이터 저장·SQL은 바꾸지 않는다.
- 실제 실과 PPT 양쪽에서 `1~16쪽 원본 → 17쪽 수업 앱 → 18쪽 활동 결과 → 19~21쪽 원본 17~19쪽`을 확인했다. 가이랩의 현재 표시도 `18 / 21쪽 · 활동 결과`로 확인했다.

이전 v0.28.1에는 다른 파트를 방문한 뒤 앱을 넣을 때 정규화된 화면 사본을 저장 기준으로 쓰던 거짓 충돌을 수정했다. `app/app.js`의 마지막 저장 성공 사본 `persistedRecord`를 사용하며 실제 외부 편집 충돌 보호는 유지한다. 다른 창에서 시작한 초안은 여전히 명시적 비교/채택이 필요할 수 있다.

## 7. 다음 작업 우선순위

1. 이번에 남긴 실제 HTML 재열기·마우스/터치·실물 휴대폰/태블릿 검수. 사용자는 현재 수동 검수를 보류했으므로 반복 확인 요청을 하지 않는다. 도구 정책이 바뀌거나 사용자가 직접 확인할 때 결과를 갱신한다.
2. 가이X 생성 앱의 수업 적합성·접근성·터치 품질을 교사 관점에서 검수한다. 생성 성공만으로 모든 임의 앱의 기능 품질이 보장되지는 않는다. HTML에서 추가한 결과를 원래 PPT 자료로 명시적으로 다시 가져오는 기능은 아직 없다.
3. PPT 계정 백업·새 기기 복구·다른 계정 접근 제어·학생 참여·제출·결과·서버 채점/순서 활동 정답 은닉의 운영 연결은 기존 PR #76과 SQL을 통합 검토한다. 새 운영 DB migration이 필요한 작업은 현재 ‘PPT·편집기 먼저, 운영 DB 변경 없음’ 범위와 다르므로 사전 설명이 필요하다. 기존 유료 QA 프로젝트를 임의로 사용하거나 운영 데이터로 부하 검사를 하지 않는다.

## 8. 다음 담당의 실행 기준

1. status·HEAD·remote·AGENTS를 확인하고 본문 보존 해시와 기존 PR 상태를 대조한다. 이 문서 작성 뒤 다른 작업자가 변경했을 수 있으니 과거 문서의 버전을 현재 코드로 덮어 가정하지 않는다.
2. 공통 수정은 원본에서 커밋한 후 가이랩의 `docs/minican.md` 절차로 `node scripts/sync-onbatang.mjs ../onbatang <확정 SHA>` 및 `--check`를 실행한다. `dist/minican/`을 직접 패치하지 않는다.
3. 공통 `npm test`; 가이랩 `node --test --test-concurrency=2 test/*.test.mjs`, `npm run build`를 실행한다. 빌드의 공개 provider 설정을 유지하고 기존 수정 파일을 복원한다. 필요한 브라우저 검사는 `MINICAN_PLAYWRIGHT_PATH`로 번들 Playwright 경로를 지정한다. 실제 계정·AI 요청을 fixture 검사에 섞지 않는다.
4. 공용 배포는 `node tools/build-firebase-hosting.mjs <확정 공통 SHA>` 및 `--check` 후 `firebase deploy --only hosting:onbatang --project onbatang --non-interactive`. 확정 Git 정적 파일만 배포하고 `work/` 전체를 공개하지 않는다.
5. 가이랩은 Korean semver note → 빌드/검사 → PR → 정확한 Netlify preview commit·badge → main 반영 → 운영 metadata·실제 UI·공통 SOURCE/HTTP 해시 확인 순서다. GitHub 결제 문제로 멈춘 검사를 성공이라고 보고하거나 결제 설정을 임의로 바꾸지 않는다.
