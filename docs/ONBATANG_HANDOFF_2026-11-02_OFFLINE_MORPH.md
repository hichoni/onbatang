## 사용하는 방법

두 장 이상에서 움직임의 ‘모핑 · 카메라 직접 편집’으로 요소를 연결하고 저장한다. ‘내려받기 → HTML 수업’을 선택하면 연결·카메라 구도·전환 시간을 담은 한 파일을 만든다. 이 파일은 인터넷 없이 앞뒤 이동과 발표 모드에서 모핑을 재생한다. 기존에 받은 HTML에는 모핑 데이터가 없으므로 원래 자료에서 다시 내려받는다.

활동과 결과 저장, 현재 수업 다시 내려받기, 온바탕용 결과 JSON은 기존 경로를 유지한다. 결과를 추가한 HTML에서도 원래 슬라이드의 모핑은 남는다. 기기의 동작 줄이기를 따르며 화면 크기를 바꾸거나 빠르게 이동하면 전환을 현재 장으로 정리한다.

## 구현 계약

- 전체 자료의 표시 순서(숨긴 쪽 제외)에서 모핑의 앞뒤 장에만 추가 그림을 담는다. 기존 여러 파트 수집 경로를 이용한다.
- `src/export.js`의 `designToHtmlFlow`는 원본을 수정하지 않고, 각 요소를 투명 PNG로 그린다. 기존 렌더러의 글꼴·부분 서식·그림·crop·도형을 사용하며 회전/뒤집기/투명도는 재생 때 한 번 적용한다. 카메라 투영도 위치·크기에 한 번만 적용한다.
- PNG에는 재배포 글꼴 파일이나 외부 이미지 주소가 필요 없다. 요소 한 장의 디코딩 크기는 긴 변 2048px/400만 픽셀 이내이며 모핑 이미지를 포함해 기존 수업 데이터 200MB 한도를 검사한다. 모핑이 없는 장에는 추가 그림을 만들지 않는다.
- `app/html-lesson-flow.js`는 제한된 JSON/PNG만 허용하고, 원본 요소 ID·복제 연결·명시적 `morphKey`를 기존 `matchItems`/`playTransition` 엔진에 전달한다. 원본 이미지 주소는 매칭용 해시로 바꾼다. HTML/CSS 문자열을 가져와 실행하지 않는다.
- 요소 PNG를 읽는 동안 앞 장의 전체 PNG를 유지한다. 읽기 실패·취소·화면 크기 변경은 도착 장 전체 PNG로 복구한다. 끝난 전환의 비동기 콜백이 다음 장에 효과를 다시 붙이지 않도록 세대를 검사한다.
- 전환 중에만 요소 그림을 겹쳐 이동하고, 도착하면 원래 전체 PNG를 다시 표시한다. HTML 그래픽 효과는 모핑 종료 후 원래 위치에서 시작한다.
- 기존 `version:1` 파일에 선택적 `page.flow`를 추가한다. flow가 없는 기존 파일·활동·결과의 의미는 바꾸지 않는다. CSP의 `connect-src 'none'`, `frame-src 'none'`을 유지한다.

## 확인된 범위

- 공통 전체 단위 412/412 통과. 새 검사는 레거시 호환·원본 불변·연결/해제·형식/크기 검증·스크립트 문맥 탈출을 포함한다.
- 실제 Edge의 새 HTML 모핑 2/2와 기존 오프라인 활동/저장/500쪽 한도 3/3 통과.
- Windows WebKit에서 새 HTML 모핑 2/2 통과. 실제 iPhone 검사와 구분한다.
- 기존 편집기 모핑 연속성 1/1, HTML 결과 되가져오기 1440/390px 2/2 통과. 되가져오기 검사는 ‘내 그림’의 비동기 저장/이동 완료를 기다린 뒤 새로고침하도록 보완했다.
- 99% 모핑 프레임과 도착 PNG의 픽셀 차이도 비교해, 종료 순간 요소의 크기/위치가 튀지 않는지 검사했다. 모핑 뒤 그래픽 효과 버튼도 작동한다.
- 자체 작성한 글·도형·사진·숨긴 장·활동으로 실제 내려받기 UI를 통과했다. 오프라인 file URL에서 0/50/99% 프레임의 위치·크기를 검사하고 역방향 2.4초, 연속 이동, 세로/가로 크기 변경, 동작 줄이기, 결과 저장, 새 파일 다시 열기와 발표 모드를 확인했다.
- 작업용 예제·스크린샷·테스트 로그는 무시되는 `work/html-morph-*`와 `work/offline-morph-*.log`에 둔다. 개인 PPT나 학생 자료를 쓰지 않았다.
- 운영 온바탕과 운영 가이랩에서 새 Edge 브라우저의 로컬 예제를 직접 내려받아 각각 2/2 통과했다. 별도 오프라인 브라우저에서 모핑·역방향·결과 저장·재다운로드를 확인했다. 실계정 동기화 검사와 구분한다.

## 범위 밖

일반 글·도형·사진 등 정적 요소 사이의 모핑이다. 활동·바탕 영상·웹·실시간 바탕 및 유튜브/웹 요소가 있는 장은 기존 PNG/활동 경로를 유지한다. 서로 다른 비율의 장 사이에는 모핑하지 않는다. 요소별 등장/강조/반복 애니메이션 전체나 PowerPoint 네이티브 Morph를 내보내는 기능은 아니다. 모핑 중 글과 그림은 PNG이므로 원래 편집기처럼 선택해 고치는 요소가 아니며 큰 확대에서는 래스터 해상도 한도가 있다.

실제 교사 PPT의 다양한 요소, 실제 iPhone/태블릿, 실계정 동기화는 이번 검수 범위 밖이다. 운영 DB·SQL·Auth와 원본 자료는 변경하지 않는다.

## 다음 담당자가 이어가는 방법

두 저장소의 작업 트리와 최신 `origin/main`을 먼저 확인한다. 가이랩의 `dist/minican/`를 직접 수정하지 말고 공용에서 수정·커밋한 뒤 `scripts/sync-onbatang.mjs`와 `--check`로 반영한다. 기존 자료/원본 PPT를 자동 변환하거나 운영 DB를 수정할 필요는 없다.

공용에서 `npm test`, 필요한 경우 `node tools/build-html-lesson.mjs`와 `node tools/build-pptx-import.mjs`로 생성물을 맞춘다. `MINICAN_PLAYWRIGHT_PATH`에 해당 환경의 Playwright 모듈을 지정하고 `node --test --test-concurrency=1 tests/browser/html-morph.test.mjs`를 실행한다. WebKit은 `MINICAN_BROWSER=webkit`과 설치된 브라우저 경로를 지정한다. 가이랩 검사는 `MINICAN_HOST_ROOT`를 가이랩 `dist`의 절대 경로로 지정한다. 가이랩 전체 검사·번들 빌드와 제품 버전 기록도 함께 확인한다.

운영 검수 증거는 로컬 `work/offline-morph-production-proof.json`, `work/offline-morph-production-deploy.log`, `work/offline-morph-live-onbatang.log`, `work/offline-morph-live-gai.log`에 있다. 이 파일들은 Git에 포함되지 않으므로 다른 PC에서는 본문의 PR·CI·운영 커밋을 기준으로 재확인한다. 실행 중인 테스트나 미완료 기능 수정은 없으며, 다음 할 일은 위 표의 미검수 범위다.
