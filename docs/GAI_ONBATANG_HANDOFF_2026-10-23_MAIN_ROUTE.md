## 구현한 수정

1. 기존 호스트는 준비 처리를 시작하면서 완료 플래그와 예비 타이머를 먼저 정리한 뒤 requestAnimationFrame을 기다렸다. 백그라운드 탭에서 화면 갱신이 오지 않으면 로딩을 끝내지 못할 수 있었다. 화면 갱신에 의존하지 않는 폰트 대기 제한과 마운트 시점의 예비 처리를 적용했다.
2. 실제 Edge·Chrome에서는 초기 iframe 문서가 about:blank에 머무는 별도 증상도 확인했다. 단순히 안내를 없애는 것만으로 해결됐다고 기록하지 않았다. 현재 화면에 프레임을 직접 연결하고 eager로 시작한다. 빈 문서인 경우만 한 번 탐색을 재시도한다.
3. 그래도 빈 문서가 남으면 같은 출처의 minican-app.html을 fetch하고, 기준 주소를 지정한 HTML Blob으로 같은 프레임 안에서 연다. **같은 출처·계정 저장 공간·메시지 origin/source 검사를 유지**하며 이미 로드되거나 준비 메시지가 도착한 편집기를 대체하지 않는다. 사용자에게 직접 편집기 주소로 나가라고 하지 않는다.
4. 느린 원래 탐색이 대체 다운로드 중 완료되면 원래 편집기를 보존하고 로딩 안내를 끝낸다. 화면을 떠나면 타이머·다운로드·Blob URL을 정리한다. 실패 시 빈 화면을 준비 완료로 표시하지 않고 연결 안내를 남긴다.
5. Blob으로 내장해도 공유·리모컨·수업·학생 링크가 올바른 주소를 사용하도록 가이랩 진입점과 수업 결과 화면의 기준 주소를 document.baseURI로 계산한다. 앱 격리나 접근 권한은 넓히지 않았다.

관련 구현: dist/minican-page.js, dist/minican-page.css, dist/minican-app.js, dist/onbatang-room-teacher.js, dist/onbatang-room-history.js. 공통 편집기 원본·SQL·스키마 수정은 없다.
